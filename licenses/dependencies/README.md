# Dependency license sources

`script/dependency-notices.ts` regenerates `DEPENDENCY_NOTICES.md` from the installed runtime packages and `platform-notices.json`. Normal generation uses no network. The platform inventory covers every locked optional native package in the runtime dependency graph, including its transitive dependencies, so different build operating systems produce the same notices.

Each platform record identifies its exact package name, version, npm tarball source, lockfile SHA512 integrity, declared license and full license text. Missing, changed or unused records fail generation. The `.txt` files supply exact upstream notices when a package omits a license file; each records its source. Unused overrides and changed platform override text also fail generation.

After reviewing a lockfile change, run `bun script/dependency-notices.ts --update-platform-notices` from the repository root. This reads installed exact-version packages where available. For unavailable platform packages, it downloads the recorded npm tarball, verifies its SHA512 against `bun.lock`, and extracts only its package manifest and top-level license documents; it never installs or executes the package. Review both the inventory and generated notices before committing. If upstream omits legal text, add a sourced, exact-version override and run the command again.

`bundled-provider-notices.json` also covers code already embedded in provider SDK JavaScript, which an installed dependency walk cannot discover. Each exact parent is bound to its `bun.lock` SHA512, published tarball, publisher commit and publisher lockfile. Components record their publisher lock path, exact version, declared license, integrity-verified archive source, full LICENSE/NOTICE text, and a SHA256 of the JSON-encoded text array. Normal generation verifies the parent binding and component text hashes without network requests, requires inventories for known embedding SDKs, and rejects malformed, stale, incomplete, duplicate or unused records. Installed and embedded copies of the same name/version share one entry with all distinct notice texts retained; conflicting license declarations fail.

To update this inventory, inspect the exact parent's published source maps, resolve embedded components against the publisher lockfile at its recorded commit, download each component archive without installing it, and verify its SHA512 before extracting legal text. Preserve all supplied notices, including README licensing sections when upstream omits a top-level license. Do not replace those texts with inferred authors or a generic copyright. Recheck current advisories for the exact embedded versions as well as the installed dependency tree. See [the provider SDK review](provider-sdk-review.md) for the current inventory and compatibility boundaries.

Inventory text hashes cover the original notice text. The generated Markdown normalizes CRLF to LF and removes trailing line whitespace for deterministic rendering; it does not remove or rewrite notice words, copyright lines, or license terms.
