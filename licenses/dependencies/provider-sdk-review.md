## Embedded provenance

The [bundled inventory](bundled-provider-notices.json) is part of the offline notice-generation input. It binds each parent to its exact npm SHA512 integrity and publisher commit, then records each embedded component's source, version, integrity, license and text hash. The package-manager lockfile alone does not describe these embedded copies.

- SAP 4.9.1 publisher commit: [`8ed89f83a7fecc06bf66feb1f3ccdd8148729c34`](https://github.com/jerome-benoit/sap-ai-provider/tree/8ed89f83a7fecc06bf66feb1f3ccdd8148729c34). Source-map paths resolve to 51 package versions in its [publisher lockfile](https://raw.githubusercontent.com/jerome-benoit/sap-ai-provider/8ed89f83a7fecc06bf66feb1f3ccdd8148729c34/package-lock.json). Every component tarball matched that lock's SHA512 before reading legal files. For 49 components, 360 embedded source-map contents also matched their archive files exactly; SAP utility and HTTPS proxy TypeScript sources are not included in those component tarballs, so their versions rely on the publisher lock. Their license texts still come from verified archives. All 51 declared licenses are MIT except SAP utility (Apache-2.0) and inherits (ISC).
- Merge 0.3.0 publisher commit: [`ac714952ffa2d2b5301fba17a80808a3c19e0fc0`](https://github.com/merge-api/merge-gateway-ai-sdk-provider/tree/ac714952ffa2d2b5301fba17a80808a3c19e0fc0). Its package manifest and compiled version identify 0.3.0 although the publisher lock's root version remains 0.2.0. The [lockfile](https://raw.githubusercontent.com/merge-api/merge-gateway-ai-sdk-provider/ac714952ffa2d2b5301fba17a80808a3c19e0fc0/package-lock.json) resolves Zod 4.3.6; all 225 Zod source-map contents across the published bundles match that exact integrity-verified Zod archive, providing an independent content check.
- `agent-base@6.0.2`, `https-proxy-agent@5.0.1`, `assert-plus@1.0.0` and `node-rsa@1.1.1` omit top-level license files but include complete license sections in their verified published READMEs. Exact excerpts and archive integrities are preserved in their `.txt` overrides. The additional node-rsa Tom Wu notice is retained.
- `@ai-sdk/provider-utils@4.0.52` omits its top-level LICENSE. Its override uses the upstream release tag's immutable commit [`5d69aa444fe9eb0c1dc1fe45c0993a7b4b27f2ba`](https://github.com/vercel/ai/tree/5d69aa444fe9eb0c1dc1fe45c0993a7b4b27f2ba) and also reproduces the bundled `src/to-json-schema/zod3-to-json-schema/LICENSE` directly from the integrity-verified package. The stale older-version overrides were removed after clean dependency installation.

## Security and compatibility checks

Exact-version [OSV batch queries](https://google.github.io/osv.dev/post-v1-querybatch/) on the review date returned no advisory matches for the 51 embedded SAP versions, embedded Zod 4.3.6, all six selected SDK versions, provider-utils 4.0.52, assert-plus 1.0.0, and node-rsa 1.1.1. No pagination tokens were returned. This is a time-specific database result, not an assurance about undisclosed issues or unreviewed runtime dependencies; rerun an installed-tree audit and embedded-version queries before release or when updating an artifact.

The reviewed [provider-utils unbounded response advisory GHSA-866g-f22w-33x8](https://github.com/advisories/GHSA-866g-f22w-33x8) affects the prior 4.x versions below 4.0.33. Vector resolves the reviewed 4.0.52 version. A lockfile override alone initially left stale local peer dependency links; a clean install was needed to verify actual resolution and remove the obsolete notices. Production builds must use the reviewed lock and verify the installed graph, rather than assuming a changed lock has rewritten existing links.

The embedded SAP HTTP components are specifically Axios 1.19.0, follow-redirects 1.16.0 and form-data 4.0.6. A root-level override cannot upgrade copies embedded inside the SDK. Updating those copies requires a reviewed replacement SDK artifact or an explicit, source-reviewed rebuild with refreshed inventory. No lifecycle or native install hooks were introduced for these provider packages; development `prepare`/`prepublishOnly` commands are not a reason to trust or execute their source repositories during installation.

Adapter acceptance remains separate from notice collection: require V3 execution tests, explicit per-instance SAP credentials rather than process-wide mutation, removal of AIHubMix's referral identity, bounded/redacted watsonx IAM handling, actual Cloudflare outer transport/cancellation, and a user-configured QVAC server without automatic runtime provisioning. Those behaviors are covered by the provider integration work; license inventory alone cannot validate them. Provider service terms, user credentials, model availability and branding rights remain with their respective providers.

## Repeatable update procedure

1. Pin the parent artifact and inspect its published source maps before installation. Find every embedded package path, including dependencies classified as development-only by the publisher.
2. Resolve those paths at the publisher's recorded source commit. Verify each downloaded archive against the publisher lock's SHA512 before reading package identity and legal files. Read files in memory; do not execute scripts or extract arbitrary paths.
3. Preserve all LICENSE, NOTICE, COPYING and relevant README licensing text. Use exact upstream attribution; an SPDX declaration without a shipped license requires an explicitly sourced override, not an invented author line.
4. Query current advisories for those exact embedded versions and for the clean installed graph. Check new API versions, process execution/native hooks, request destinations, credential handling and cancellation separately.
5. Update the inventory and overrides, run the compliance tests from `packages/engine`, regenerate `DEPENDENCY_NOTICES.md`, and review the result. Generation rejects missing required inventories, stale parent integrities, altered text hashes, duplicate/incomplete records, unused records, and conflicting installed/embedded license declarations.
