The contract is [vector-at-mention-spec.md](./vector-at-mention-spec.md). Record here every correction that keeps the contract's intent, in the same commit as the code that needs it, newest last. Use one heading per package, `## <YYYY-MM-DD> <package id> (<package title>)`, and number each item. Say what the contract said, what was built instead, why, and which later packages or lanes it affects.

The first section is different: it lists where the contract itself departs from the Codium contract's §4.18 amendments and related SPEC text (`origin/codium:docs/vector/build/codium-build-spec.md`). ## 2026-10-30 Contract (departures from SPEC §4.18 decided before V00)

1. **Amendment 2, "add a `run` audience".** The contract adds two per-endpoint audiences, `mint` and `bind` (spec 2.10), so a bind token can never mint and a mint token can never bind. The intent (a dedicated audience for run credentials, separate from `token` and `installation`) is kept. A59 needs no audience change.
2. **Amendment 9, "a per-run key the server gives after the OIDC check".** Session artifacts are encrypted under a key per conversation (thread) and binding generation, given only to a valid run token whose signed `thr` claim names that thread (spec 2.8, V27, INV-P5). A per-run key could not decrypt the previous run's session, which is the point of the artifact. Privacy copy says "encrypted per conversation".
3. **Amendment 10, "free a slot when the same check run mints again".** A second mint from a live check run renews the token in place: same reservation, same start and deadline, new `jti`, no extra charge, and the earlier token stops working (spec 2.6, INV-S9). Freeing and re-reserving would let a re-mint loop extend a run past the plan's longest run.
4. **Amendment 14, "register the App with the webhook from day one".** The App is registered with Deployments: read from day one, but the webhook is saved only after Codium's A47 router is deployed (section 4 step 3). Until then the mint's owner-id check catches transfers (INV-S11).
5. **SPEC §4.10 codes at the mint.** The mint answers one neutral 403 `BINDING_UNAVAILABLE` for the allowance reasons `none`, `payment`, `dispute`, `fraud`, `closing` and `not-in-plan` (`github-agents`), with no `reason` field, instead of `MODEL_PLAN_REQUIRED`, `MODEL_PLAN_PAYMENT_REQUIRED {reason}` and `MODEL_PLAN_ACCOUNT_CLOSING`. Mint responses reach workflows any writer controls and public logs, so they must not reveal the binder's billing state (P6). The contract also adds `limit: "scheduled"`, `RUNNER_NOT_SUPPORTED` and `BIND_NEEDS_DEFAULT_BRANCH`, and maps a mint-time service-off to `MODEL_PLANS_DISABLED` (spec 2.9.1).
6. **The scheduled-runs cap counts GitHub `schedule` events only.** A separate workflow that dispatches `vector.yml` on a timer makes `github-dispatch` runs, which the cap does not count. This is an accepted risk: the hours cap and runs-at-once still bound them, and copy never calls the scheduled cap unbypassable (INV-C4).
7. **Publishing credential.** SPEC A49 builds Ship Desk cards from App-bot-authored PRs, and the earlier draft published server-started runs with the App token "so CI runs". The contract publishes with `GITHUB_TOKEN` by default and always for server-started runs, because App-token pushes start the repository's own workflows with its secrets on unreviewed, possibly prompt-injected code (INV-S18, O14). Vector's PRs are therefore `github-actions[bot]`-authored unless a repository opts in. Affects Codium A48, A49 and A50 (spec section 5).
8. **Pre-A59 entitlement backing.** Until A59, `cloudAgentEntitlement`'s default `plan()` reads `modelPlanStatus`, which can settle a pending top-up under the billing lease, reads the OpenRouter management API, and reports a `renewing` plan as inactive (SPEC §4.4 allows new mints while renewing). This is accepted because the backing is dormant: the kill switch stays unset until A59 replaces the function body with `cloudAgentAllowance` (spec 2.3, O10).
9. **"Remove sudo" (the earlier draft's O3) is replaced by the agent sandbox.** Removing the runner's sudo did not stop a same-user process from reading other processes' environments, and left the runner in the `docker` group. The model now runs as a separate user with no sudo and no Docker access (spec 2.11.3, V16). This strengthens amendment 3 rather than departing from it, and is listed here because the earlier draft of this contract proposed "Remove sudo" as O3's default.
