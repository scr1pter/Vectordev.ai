  "unpriced" or "Cost unknown" beside Codium work. Feature branch only.
- Usage (A23): Settings → Usage and the usage check-ins still count Codium tokens, because `summarizeUsage` reads
  messages, not session totals.
- `vector stats` (A25, C9): it does not use `summarizeUsage` (`aggregateSessionStats`,
  `packages/engine/src/cli/cmd/stats.ts:93`), and its paths now disagree. Without `--days`, its token totals (and the
  helpers row's tokens) read the session totals (`:208-221`), so from A22 they leave Codium tokens out. With `--days N`
  it sums per-message tokens instead, V1 `message.info.tokens` and V2 row `data.tokens` (`:183-204`), and its
  per-model rows always sum V1 `message.info.tokens` (`:232-251`); those records keep Codium tokens (D-2), so they still
  count them. A Codium session's `vector-plan/<model>` row therefore lists tokens the all-time Total Tokens leaves out,
  and `--days 7` puts them back into the total; before A22 all three agreed. A scratch test (run once from
  `packages/engine` through `vector-serial`, then deleted) showed it: one Codium step of 10,000 input tokens gave
  all-time input 0, a `vector-plan/m` row of 10,000 and `--days 7` input 10,000, with the session row at tokens 0,
  `codiumSteps` 1, `unpricedSteps` 1. `stats.ts` is left unchanged in A22, because C9 owns its Codium filter and text.
- Guard (A23, D-3): Codium steps stay cost kind `"unknown"` in SpendGuard, so the existing 40-unpriced-step stop under
  a dollar cap still fires for Codium runs, as today.
- No backfill: test sessions with Codium steps recorded before A22 keep mixed totals; their flagless records count as
  ordinary steps when added and when subtracted, so no count goes negative.
- Every Codium step is unpriced and Codium, including a zero-token one (contract §4.1), which differs from the "a step
  that used no tokens owes nothing" rule for other models but keeps `codium_steps ≤ unpriced_steps`. A Codium step's
  admission settlement (Vectorscope reviews, distill) is therefore always marked incomplete, as it already was for any
  Codium step that used tokens.
- `updateMessage` stamps a published copy: in-memory assistant objects callers keep (the processor's
  `ctx.assistantMessage`) carry no flag, so an in-memory display reader must use `Billing.of`.
- A user-configured custom provider named `vector-plan` would be stamped as Codium (low risk; provider policy and the
  Codium plugin own the id, as A21 recorded).
