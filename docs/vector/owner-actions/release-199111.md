# Desktop 1.99.111: release notes and owner steps (draft)

Desktop 1.99.111 brings Deep research (preview) with a browser for each research agent, Vector Local in the desktop app, local models that fit Vector, memory of you in every agent, and learning about you. It builds from one main commit, like every release. This file is a draft written before the release: no version is bumped yet (`packages/desktop/package.json` still says 1.99.110), and the notes below go into `packages/web/src/data/vector-releases.ts` and `packages/web/public/changelog.json` only in the release preparation commit.

The required npm CLI stays at 1.99.99 (`vectorRequiredCliVersion`) unless you publish a new CLI first. So `vector local`, `vector run --local`, `vector run --research` and the rest of the terminal side arrive only with a new CLI release, and Windows WSL servers keep the 1.99.99 engine, which has none of this, until a later desktop release requires that CLI. The docs pages say so.

## Release notes (draft)

These go into the 1.99.111 entry of `release199` word for word. The desktop's What's new and the GitHub release notes are made from them. If `browser-search` is merged first (see step 1), replace the sentence that begins "Research searches through" with what that branch ships.

**Title:** Deep research (preview), Vector Local in the app, and memory of you in every agent

**Summary:**

Deep research arrives as a preview: pick Deep research in the composer's Mode menu and Vector plans the question with you on a card, searches and reads the web and this repository's brain, and writes a report in which each claim cites a quote Vector found in its source, with Vector's estimate of how well the sources support it. It makes no code changes. Focused uses one agent, plus up to 2 researchers when the question has independent parts; Deep adds up to 4 researchers and a judge that checks the citations. In the desktop app every research agent reads in a browser of its own, with no cookies or sign-ins, that only reads and goes through Vector's research proxy, and the Sources tab shows each one as view-only snapshots with Stop. Research searches the web in each research agent's own isolated browser, with no search service or key to configure; if search is blocked or unavailable it says so and uses the brain, the repository's files and the links you paste. It does not solve CAPTCHAs, disguise the browser or rotate addresses. Vector checks outgoing searches for text from your private files, reads only addresses from search results, page links or your own message, follows robots.txt for links it finds, and keeps only the public excerpt of a paywalled page. Reports and their sources stay private in the repository's brain until you keep them, runs you do not keep are deleted after 30 days, and default caps ($1 and 80 steps for Focused, $3 and 240 steps for Deep) apply when you have no spend cap of your own. The build agent can also research as part of its work on Work and Thorough requests. Vector Local comes to the desktop app: Settings → Vector Local, or Models you host in Getting started, finds the Ollama, LM Studio, vLLM, llama.cpp or SGLang servers on this computer, adds a server elsewhere by its address and keeps its identity, checks each model for the role it fills and turns Vector Local on. With it on, the agent, subagents, the judge, Vectorscope, Deep research, memory search and the helpers that write titles and summaries use only the model servers on your list, Vector blocks its own requests to vectordev.ai and to AI services that are not on the list unless you allow one, and the network log, What Vector sent, lists by origin what Vector's engine and windows sent or blocked, kept for 30 days on this computer. Free models provided by Vector, Vector Codium, cloud providers, share links, automatic update checks, usage counts, crash reports, release notes, the help assistant and outside agents are off while it is on, each labelled Off in Vector Local. Web access (Ask, Your network only or None) decides what research and the browser may read, and with None the agent's shell commands run in Vector's sandbox on macOS and Linux. A change that would loosen Vector Local waits for you, and a company can lock it with a policy only an administrator can change, with its own certificate authorities and update mirror. Vector Local is a policy inside Vector, not a firewall: programs the agent starts make their own connections, MCP servers and language servers run outside the sandbox, and Windows has no sandbox. Models on servers you host fit Vector better whether or not Vector Local is on: Check models sets each model's reply limit and how many requests its server takes at once, a server takes one request at a time unless that is set, with Vector's own titles and summaries waiting behind your requests, a model whose context is too small for its role is refused with the fix, Fast is not offered for them, and steps on this computer or on a listed server on your network have no per-token price while step and loop limits still apply. Every agent now uses what Vector has learned about you: subagents of every size get up to 100 tokens of how you work, the Vectorscope reviews you run in Vector get up to 300 tokens of how you review, chosen with the changed files, and Deep research's researchers get the formats, sources and style you prefer, never facts about you. Sessions with invited guests, and free models that may train on your prompts, get none of it. Before Vector posts a pull request or a review, or makes a commit, it checks the text against what it knows about you and shows you what overlaps. Vector also learns about you from what you type, not what you paste: what you mean by your words, and the formats, workflow, tools, sources and style you prefer, each shown as a Learned line with Undo and listed in the new Settings → Memory → About you, where you can edit or forget each one or stop Vector learning a kind. Settings → Memory also gains Research and Export and import, and up to 300 entries about you stay in use. The agent browser now cancels downloads and grants a page no permission but fullscreen, and Always allow for a web page covers that site only. The terminal's vector local, vector run --local and vector run --research come with the next CLI release, and Windows WSL servers keep running the 1.99.99 engine, without them, until a later desktop release requires the new CLI. This release is not yet code-signed, so a new install may show an operating-system warning on first launch.

## Before you release the desktop

1. **Merge what 1.99.111 needs into `local-research`, then main.** The other 22 phases and the hard-r1, hard-l3 and hard-l4 hardening are merged into `local-research`; this phase (X1, branch `ph-x1`) merges last. Two branches are not merged yet:
   - `browser-search`: the release integration replaces the retired search providers with each calling agent's own research browser and updates the setup UI, docs, plan estimates and tests. Old search settings still load and are ignored.
   - `outbound-simple` (the outbound check cut to high-confidence signals). The research page's paragraph on the check names only what both versions refuse, so it holds either way.
   Merging `local-research` into main will meet main's docs changes since 22 Oct (the local memory page removed, `publishedDesktopVersion` at 1.99.110). Keep both sides.
2. **Run the checks nobody has run yet.** Each is a check of the real thing that the unit tests cannot be:
   - **Gate L2 (packet capture). Not run yet.** Run `bun scripts/local-mode-smoke.ts` from `packages/desktop` on a Mac with a display (it needs Electron's binary) while capturing packets, then drive a 30-minute session with Vector Local on and compare the capture with What Vector sent. Nothing about the network log may be marketed until this passes.
   - **Research browsers in real Electron. Not run yet.** `bun scripts/research-browser-smoke.ts` from `packages/desktop`. Until it passes, cookie isolation between research browsers, the loopback refusal, service workers, dialogs, print, freezing and the client-certificate refusal are tested only with Electron mocked.
   - **A 30-minute Deep research session on a local model, with timings. Not run yet.** On a Mac with Ollama and a tool-calling model the agent fits (Check models says Works), run one Focused and one Deep research question with Vector Local on and Web access Ask, and record the time to the plan card, the time to the report, the steps and the pages read. Gate G-Fit also needs a 4-researcher Deep run on one local slot to finish.
   - **The macOS shell sandbox (seatbelt). Run on 23 Oct, macOS 27.0.1.** `packages/engine/test/tool/shell-sandbox-local.test.ts` passed on this Mac (8 pass, 3 skipped because they are for Linux or Windows): with Web access None a command cannot reach another computer, still reaches a server on this computer, and is told once what the sandbox limits. `packages/engine/src/tool/shell/sandbox.test.ts` passed 23 of 24; the one failure, "linked worktrees keep shared objects, refs, and reflogs read-only", came from running it in a checkout under `/private/tmp`, a folder the sandbox lets commands write as a temporary folder, so its "escape" file was writable there. Run it again from a checkout outside `/tmp` to confirm.
   - **The air-gap CI job. Not run yet.** Check its first run, especially the `sudo unshare --net` step and bubblewrap after the AppArmor setting.
   - **Model server recordings. Not done yet.** The server answers under `packages/core/test/fixture/local-servers` were written from each server's docs. Record them from real Ollama, LM Studio, vLLM, llama.cpp and SGLang servers before relying on the field names.
3. **Decide what the build leaves open:**
   - The composer has two menus headed Mode: the speed menu (Normal, Quick, Fast, Deep research) and the approval menu (Manual, Plan, Full access).
   - A learned instruction that names a person, a client, an email or a host stays in the repository's memory, which invited guests and free models that may train can see.
   - A model server's update, or an `ollama pull`, holds it until you confirm it, because its identity includes its version and models.
   - A server that does not answer Vector's identity check is not held, and its model calls go ahead.
   - `vector memory erase` in the terminal leaves Deep research runs (their questions, plans and notes); the app's Tidy and erase and Erase all research remove them. Fix it before the next CLI release.
   - A person's own config can shorten the network log's retention to 1 day; a company that needs a longer one sets it in its policy.
4. **Legal review.** The privacy policy does not describe what 1.99.111 adds: the network log (origins only, kept on this computer for 30 days), Deep research saving the text of the pages it reads into `brain.db` (up to 40 MB a run and 1 GB a repository, runs you do not keep deleted after 30 days), the sites and search services research sends requests to, and the posting check, which runs on this computer. Legal text changes only with your sign-off.
5. **Start the release** with the Codex release prompt for 1.99.111, written once CI is green on the release commit, or by hand. The preparation commit sets `packages/desktop/package.json` to 1.99.111, adds 1.99.111 to `unsignedVersions` in `packages/desktop/release-policy.json` if it ships unsigned, adds the entry above to `release199`, and runs `bun scripts/build-changelog.ts` from `packages/web` to write `public/changelog.json`. ## Not in this release

- **Deep research is a preview.** It stays labelled Preview until Gate G-R and Gate G-Fit pass.
- **Browser search** needs the desktop's research-browser bridge. Where that is unavailable, research says that nothing was searched.
- **Config keys that are read later:** `research.depth`, `research.retain_days` and `research.browser_search`, and `local.models_dir` and `local.catalog_path`. Their descriptions say so.
- **Research on the V2 runner** (core's `SessionV2`) is Focused only, searches through its own research browser when the desktop bridge is available, and carries no memory of you. Its plan card says Deep's researchers and judge are not on that runner yet.
- **Research browsers** do not run in the terminal, WSL, remote servers or headless runs; there research lists a page that needs a browser as skipped.
- **No queue position** is shown while a request waits for a model server's slot.
- **Allow once** is offered only for Vector's own downloads; other services get Always allow.
- **The terminal's `vector upgrade`** does not read a company's update mirror yet.
- **Find servers in WSL** asks only the distribution's own loopback; a server on the Windows side is added by its address.
- **The posting check** does not check commands the agent runs itself, such as `git commit -m` or `gh pr create`, and reviews that run in GitHub Actions have no brain.
- **The learned chip** under a reply lasts only while the window is open; About you and Recently learned keep everything.

## Changes people will notice

- The composer's speed menu is headed **Mode** and lists Deep research under Fast. Fast is not offered for a model on a server someone hosts.
- **Always allow** for a web page or the agent browser now covers that site, not every site, so a new site asks once.
- The agent browser cancels downloads ("Downloads are off in the agent browser.") and grants pages no permission but fullscreen.
- Subagents of every size now start with up to 100 tokens of how you work, and Vectorscope reviews you run in Vector with up to 300 tokens of how you review.
- Up to 300 entries about you stay in use, where 1.99.110 kept 120.
- Vector learns about you only from what you type: text you paste into the composer is marked as pasted and left out.
- A model on a server someone hosts now replies within a limit Check models sets, and a server takes one request at a time unless Check models or you set more.
