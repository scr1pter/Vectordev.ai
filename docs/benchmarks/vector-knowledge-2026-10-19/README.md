## What it measures

The fixture is a small invented repository of 25 source files and 5 short specs for it (`packages/core/test/fixtures/knowledge`): 1,792 characters, about 423 tokens, read into 34 records. Recall runs the way a Light request does: the request's words, the files it touches, and at most the Light budget of cards. No model is called and nothing is embedded.

- **40 tasks** name the files they touch, mostly in words the governing requirement never uses ("change how long people stay signed in" while editing `src/auth/session.ts`).
- **8 tasks** edit a file that only imports the governed one, so no spec is linked to the edited file itself.
- **10 requests** ask about nothing the specs say, such as "hi" or "how do I center a div?".

A task counts as found when the governing requirement's sentence is in what the request carries.

## Keyword stage

The 5 specs were searchable by keywords and linked to the code 0.33 s after the first was added, read on the main thread as the test fixture reads them. A Light recall took 1.4 ms at the median and 2.9 ms at the 95th percentile.

A generated 300-page text PDF (1.0 MB, about 169K tokens if sent whole, 2,000 records in 540 passages) was searchable by keywords 3.89 s after it was added, read in the background worker. 20 of 20 questions about it recalled cards, at most 221 tokens each as Standard requests, in 15.1 ms at the median and 19.4 ms at the 95th percentile.

## Limits

- The fixture is small and was written alongside the feature it measures. It shows that code links reach requirements keywords miss; it is not an independent benchmark, and it does not measure the quality of a model's answers.
- Times are from one run on the machine named above and change with the machine and its load.
- Search by meaning (local embeddings) is not in this build, so its column has no figure.
- Token counts are Vector's estimate of what the recalled text costs, not a provider's count.
